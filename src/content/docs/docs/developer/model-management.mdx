管理器里有两类模型：八套 TTS 引擎（含多尺寸变体）与 Whisper 转录模型。每个模型都对应 `backend/backends/__init__.py` 里的一条 `ModelConfig`，首次使用时从 HuggingFace Hub 下载并缓存到平台标准目录。

在 Apple Silicon 上，Qwen TTS 用 `mlx-community` 的 MLX 优化仓库而不是 PyTorch 仓库，由 `get_backend_type()` 自动选择。CustomVoice 与 VoiceDesign 只有 PyTorch 版本，上游没有发布 MLX 转换。

Qwen VoiceDesign 只有 1.7B 一个规格，没有 0.6B 变体。它是唯一消费 `voice_type: "designed"` 配置文件的引擎：声音身份来自配置文件的 `design_prompt`，而不是参考音频或预设 ID。

## 进度上报

下载进度通过 Server-Sent Events 推给前端，链路由三部分组成：

- **`ProgressManager`**（`backend/utils/progress.py`）— 内存中的 `model_name → {current, total, filename, status}` 映射
- **`HFProgressTracker`** — 上下文管理器，拦截 HuggingFace Hub 下载并发出字节级进度。因为 `huggingface_hub` 在 PyInstaller 冻结构建里会静默关闭 tqdm，这一层是必需的
- **SSE 端点** — `GET /models/progress/{model_name}`，持续推送直到 `status` 为 `complete` 或 `error`

```javascript
const eventSource = new EventSource(`/models/progress/${modelName}`);
eventSource.onmessage = (event) => {
  const { current, total, status } = JSON.parse(event.data);
  updateProgressBar(current / total);
  if (status === "complete") eventSource.close();
};
```

## 模型状态

`GET /models/status` 返回所有已注册模型的当前状态：

```json
{
  "models": [
    {
      "model_name": "qwen-tts-1.7B",
      "display_name": "Qwen TTS 1.7B",
      "engine": "qwen",
      "downloaded": true,
      "size_mb": 3500,
      "loaded": true
    }
  ]
}
```

处理函数遍历 `get_all_model_configs()`，对每条调用 `check_model_loaded(config)`，因此新引擎只要注册进 `ModelConfig` 就会自动出现在这里。

## 手动操作

| 方法 | 端点 | 说明 |
| --- | --- | --- |
| GET | `/models/status` | 所有已注册模型的状态 |
| POST | `/models/load` | 把 TTS 模型载入内存 |
| POST | `/models/unload` | 从内存卸载 TTS 模型 |
| POST | `/models/download` | 触发后台下载 |
| GET | `/models/progress/{name}` | SSE 推送下载进度 |
| DELETE | `/models/{name}` | 从缓存删除已下载模型 |

### 加载

```http
POST /models/load
{ "model_name": "qwen-tts-1.7B" }
```

路由会查出配置、交给 `get_model_load_func(config)`，模型就绪后返回。`model_name` 可以是 `/models/status` 里的任意 ID——TTS、Whisper 与 LLM 条目都走同一个注册表。省略 `model_name` 时回落到默认 Qwen TTS 后端，可用 `model_size` 指定尺寸（`POST /models/load?model_size=0.6B`），这是引入 `model_name` 之前的写法，仍然可用。

### 卸载

```http
POST /models/unload
{ "model_name": "chatterbox-tts" }
```

调用 `unload_model_by_config(config)`，路由到对应后端的 `unload_model()` 并释放显存。`POST /models/{name}/unload` 等价。省略 `model_name` 时卸载默认 Qwen TTS 模型。

### 下载

```http
POST /models/download
{ "model_name": "kokoro" }
```

异步触发下载任务，进度走 SSE 端点。首次生成时会自动下载，所以这个接口主要用于预热。

## 预设音色初始化

对使用预设音色的引擎（Kokoro、Qwen CustomVoice），下载完成后后端会为每个内置音色自动建一条声音配置文件。逻辑在 `backend/services/profiles.py` 的 `seed_preset_profiles(engine)`，由 models 路由在下载结束时调用。

这些配置文件带有 `voice_type = "preset"`、`preset_engine`（`"kokoro"`、`"qwen_custom_voice"`）、`preset_voice_id`（`"am_adam"`、`"f000001"` 等），且没有 `profile_samples` 行。字段含义见[声音配置文件](/docs/developer/voice-profiles)。

## 新增模型

给现有引擎加一个尺寸变体，只要再加一条 `ModelConfig`：

```python
ModelConfig(
    model_name="qwen-tts-3B",
    display_name="Qwen TTS 3B",
    engine="qwen",
    hf_repo_id="Qwen/Qwen3-TTS-12Hz-3B-Base",
    model_size="3B",
    size_mb=7000,
    languages=["zh", "en"],
),
```

前端通过 `/models/status` 自动发现它，下载与加载流程无需改动。接入全新引擎则是更大的工程，见 [TTS 引擎](/docs/developer/tts-engines)。

## 错误处理

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| 下载失败 | 网络问题或 HF 限流 | 重试 |
| 加载时 OOM | 显存不足 | 换更小的变体，或卸载其他引擎 |
| 模型未找到 | 缓存损坏 | 通过 `/models/download` 重新下载 |
| 冻结构建里进度条卡住 | `huggingface_hub` 的 tqdm 被静默 | `HFProgressTracker` 会强制打开内部计数器 |
| GPU 架构不支持 | PyTorch wheel 未覆盖该显卡 | 见 [GPU 加速](/docs/getting-started/gpu-acceleration) |

生成过程如何使用这些模型见[生成管线](/docs/developer/tts-generation)。
