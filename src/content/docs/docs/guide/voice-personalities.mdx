**人格（personality）**是附加在声音配置文件上的一段可选自由文本——这个声音是谁、怎么说话、在意什么。设置之后，生成按钮旁会多出两个控件，都由内置的 Qwen3 本地 LLM 驱动：

- **创作（Compose）**——往文本框里放一句全新的角色台词，再点一次换一版。
- **按角色口吻改写（Speak in character）**——一个开关，在 TTS 之前把你的输入文本改写成角色口吻，保留每一个意思。

LLM 负责产出文本，声音配置文件负责说出来。没有云端往返，没有外部 API，整个闭环都跑在你的硬件上。

<Aside type="note" title="0.5.0 引入">
人格在 0.5.0 推出。这个本地 LLM 同时充当[全局听写](/docs/guide/dictation)的润色模型——应用里只有一个 LLM，不是两个，共享一份模型缓存和一份显存占用。
</Aside>

## 设置人格

打开声音配置文件的编辑视图。**Personality** 字段是自由文本，最多 **2,000 个字符**。怎么描述都行：他们会说的台词、说话习惯、语气、边界。

好的描述通常包含：

- 一句话身份（他们是谁）
- 说话方式（节奏、用词、避免什么）
- 有代表性的句子——示例台词比形容词更能让 LLM 抓住目标语气
- 这个角色**不会**做什么（不解释、不道歉、拒绝出戏等）

克隆型或预设型配置文件都能设置人格。无论用哪个引擎，这些模式的行为都一致。

## 两个操作

每个操作针对不同的任务，LLM 的 temperature 也会相应调整。

### 创作（Compose）

在没有种子文本的情况下生成一句全新的角色发言。点击打乱按钮，台词会直接落进生成文本框；再点一次换一版。

- **适用**：原型试听、给角色试音、还没想好台词时找灵感
- **温度**：偏高——要的就是变化
- **典型输出**：一句短促、符合角色语域的台词

### 按角色口吻改写（Speak in character）

打开人格开关后，你输入（或听写）的内容会在 TTS 之前被改写成角色口吻——每个意思都保留，只改措辞。高保真模式：内容不变，只变说法。

- **适用**：把口述备忘录变成角色发言；让平实的稿子带上特定声音的表达，不用手改
- **温度**：偏低——忠实优先
- **典型输出**：同样的意思、同样的顺序，不同的措辞与节奏

## 仅输出可朗读的内容

两种模式都强制**只输出可朗读文本**。提示词要求 LLM 产出一个人真会说出口的话：没有叙述、没有动作标签（`*sighs*`、`[laughs]`）、没有元评论、没有 Markdown 格式、没有舞台指示。

这是刻意的：输出会直接送进 TTS，任何读不出来的东西要么被忽略，要么被逐字念出来。仅口语化的约束也让结果能干净地嵌进对话，可以把创作出的台词直接放进故事。

## 本地 LLM

内置 LLM 是 **Qwen3**，有三档：

| 模型 | 下载大小 | 适用场景 |
| --- | --- | --- |
| Qwen3 0.6B | 约 400 MB | 默认。很快，适合日常使用。 |
| Qwen3 1.7B | 约 1.1 GB | 适合有特定措辞的角色人格。 |
| Qwen3 4B | 约 2.5 GB | 完整质量，最慢。适合非常讲究的语气。 |

模型沿用 Voicebox 为 TTS 采用的后端分工——Apple Silicon 上是 **MLX**（4-bit 社区量化），其他平台是 **PyTorch**（transformers 的 `AutoModelForCausalLM`）。下载走与 TTS 模型相同的缓存和模型管理界面。

在 **Settings → Captures → Refinement → Refinement model** 里选档位，人格模式复用它。切换模型后，润色和人格输出都会在下一次调用时采用新模型。

## 使用控件

当选中的配置文件设置过人格时，浮动生成框上会出现这两个控件。

<Steps>
  <Step title="创作——换一句台词">
    点击打乱按钮，LLM 运行后把结果填进生成文本框。想改就改，然后点击生成。
  </Step>
  <Step title="按角色口吻改写——打开人格开关">
    输入（或听写）你想说的话，打开人格开关，点击生成——Voicebox 先把文本送进人格 LLM，再由 TTS 朗读改写后的版本。关掉开关就是普通 TTS。
  </Step>
</Steps>

创作每次点击都会给出不同的结果。人格开关则是一种模式：它作用于之后每一次生成，直到你把它关掉。

## 典型场景

- **用你的声音说话的智能体。** 把人格开关与内置 [MCP 服务器](/docs/guide/mcp-server)结合，Claude Code、Cursor、Cline 或任何支持 MCP 的智能体都能通过带人格的配置文件回话。智能体调用 `voicebox_speak({ text, profile, personality: true })`，Voicebox 先把文本改写成角色口吻再朗读。
- **交互角色。** 游戏、叙事工具、无障碍体验。一段人格描述加一个克隆声音，就能变成一个可复用的角色资产。
- **无障碍。** 无法用原来声音说话的人，可以保留一段描述自己过去如何说话的人格，再用改写开关把打出来的文字变成角色化语音。
- **创作草稿。** 先写一份平实大纲，打开人格开关，逐句生成角色声音，再把音频放进故事。

## API 接口

人格也可以通过 REST 访问：

| 方法 | 端点 | 请求体 |
| --- | --- | --- |
| `PUT` | `/profiles/{id}` | 带上 `personality` 字段（最多 2,000 字符）即可设置。 |
| `POST` | `/profiles/{id}/compose` | 无请求体。返回一句新的角色发言文本。 |
| `POST` | `/generate` | 带上 `personality: true`，输入文本会先经过人格 LLM 再交给 TTS。`POST /speak` 同理。 |

带 `personality: true` 的 `POST /generate` 正是 MCP 的 `voicebox_speak` 工具在传入 `personality: true` 时使用的同一套原语。脚本和智能体可以直接调用。

## 限制与注意

- **人格是提示词，不是微调。** LLM 有时会跑出角色，尤其是在温度较高的创作模式下。再点一次换一版。
- **长人格不总是更好。** 2,000 字符是上限，不是目标。一段 300 字符、带两句示例台词的精准描述，通常胜过一大段。
- **仅口语化是强制约束，但不是万无一失。** 很长的提示词或特殊输入仍可能漏进动作标签。如果 TTS 输出里出现 `[laughs]`，通常是人格描述里有让模型锚定的提示——把它从描述里删掉。
- **改写比创作更严格。** 如果输出改变了你的意思，你要的大概是创作（或直接带上下文再生成一次），而不是改写。
